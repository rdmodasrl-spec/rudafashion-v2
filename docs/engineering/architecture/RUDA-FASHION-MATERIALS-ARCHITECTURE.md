# RUDA 服装生产物料库 (面料与辅料) 架构设计方案

> **状态**：架构设计 (Draft)
> **目标**：建立独立于成品服装的生产物料库，支持面料与辅料的库存管理、采购成本核算及生产关联。
> **原则**：保护现有成衣系统，避免混淆；复用现有物料模型，保持轻量。

---

## 1. 核心模型设计

### 1.1 物料定义 (Material)
物料库将直接复用并增强已存在的 `Material` 模型。它在物理存储上与 `Product` (成衣) 彻底解耦。

- **复用现状**：`Material` 模型已存在，包含 `code`, `name`, `category`, `unit`, `unitCost` 等基础字段。
- **独立性**：物料拥有独立的编码体系，不会出现在前台商城或商家 B2B 销售目录中。
- **分类管理**：
  - `category: "fabric"`：面料类（通常以“米”为单位）。
  - `category: "accessory"`：辅料类（拉链、扣子、织带等，以“件”、“包”或“米”为单位）。

### 1.2 规格与属性
为了支持面辅料的特殊性，物料库需管理以下非结构化/半结构化属性：
- **颜色/花色**：面料的核心维度。
- **技术参数**：克重 (gsm)、幅宽、成份 (Composition)、经纬密度、缩水率。
- **单位制**：支持 `meter` (米), `yard` (码), `piece` (件), `kg` (千克) 等。

## 2. 库存与批次管理

### 2.1 独立库存体系
复用 `MaterialInventoryBalance` 和 `MaterialInventoryMovement`，与成品服装的 `InventoryBalance` 物理隔离。

- **入库 (Inbound)**：关联采购单 (`MaterialPurchaseOrder`)，记录入库批次、供应商批号和入库单价。
- **出库 (Outbound)**：关联生产工单 (`ProductionOrder`)，记录领料扣减。
- **库存结余**：支持多仓库/多库位管理，区分“可用库存”与“已分配(锁定)库存”。

### 2.2 批次追踪 (Batch Tracking)
物料库存变动应支持 `batchNo`。对于面料，同一款号不同批次可能存在色差，入库时必须记录批次号，以便在生产领料时进行精确追踪。

## 3. 业务链路关联

### 3.1 供应商与采购
- **供应商关联**：`Material` 直接关联 `Supplier`。
- **物料采购**：设计 `MaterialPurchaseOrder` (物料采购单)，用于记录向面料商/辅料商的订购行为。
- **成本核算**：物料入库单价直接决定了生产的“物料成本”基准。

### 3.2 生产工单关联 (与现有系统衔接)
在不恢复 BOM 的前提下，通过“领料单 (Material Issuance)”与现有 `ProductionOrder` 关联：
1. **手工关联**：在生产工单的“物料消耗”板块，手动选择所使用的面料/辅料。
2. **库存扣减**：确认领料后，自动触发 `MaterialInventoryMovement` 的出库记录。
3. **进度追踪**：物料到位状态作为生产工单“待开工”或“生产中”的前置条件。

## 4. 未来 BOM 衔接策略

虽然本轮不实施 BOM，但设计上预留以下扩展点：
- **标准耗用**：未来在 `Product` 下增加 `StandardBom`，定义每件成衣的标准耗用量。
- **自动算料**：基于 `ProductionOrder` 的计划产量 × `StandardBom` 自动生成“建议领料量”。
- **损耗分析**：对比“标准耗用”与“实际领料”，分析生产损耗率。

## 5. 防混淆与安全原则

- **UI 隔离**：商家后台通过“生产管理 -> 物料库”进入，而非“商品管理”。
- **权限隔离**：物料库存权限 (`material.inventory.manage`) 与成衣库存权限分离。
- **搜索隔离**：全局搜索成衣时，排除 `Material` 记录。
