# RUDA 全站版块重复检测与清理审计

- 日期：2026-10-25
- 范围：商家后台 Web / 手机端、生产链（商家 + 工厂工作区）、经营主页与商品、库存、订单、客户、生产、设置、AI、通知、搜索等入口；平台后台、前台/手机前台、小程序与员工端本轮只做代码级检查。
- 原则：同一业务数字只在最合适的位置出现一次；导航入口保留唯一主入口，快捷入口必须有独立用途；不得用隐藏重复内容代替修复数据口径。
- 结论状态：商家后台 Web / 手机端已完成本轮可见重复修复并在隔离数据库真实会话中截图验证；其他运行面未完成全量视觉验收，不能标记“全站完成”。

## 3. 已修复问题清单

### DUP-01 手机端商品页同一总数显示 4 次

- 页面：商家后台手机端 → 商品。
- 修复前真实文本：`商品 | 1 | 商品 | 0 | 低库存 | 1 | 待完善 | 全部 1 | 出售中 1 | 已下架 0 | 共 1 件商品`。
- 原因：顶部统计卡、状态筛选“全部”、底部“共 N 件商品”三处分别直接读取 `merchantProducts.length` / `visibleProducts.length`，同一集合重复渲染。
- 修复：
  - 删除顶部“商品”统计卡，只保留有行动意义的“低库存”“待完善”。
  - 商品总数只由“全部 N”筛选胶囊承载；分状态胶囊保留各自数量。
  - 底部结果数仅在输入搜索词或选择品类时显示“筛选结果 N 件”，默认列表不再重复总数。
- 验证：修复后文本为 `商品 | ＋ 发布 | 0 低库存 | 1 待完善 | 全部 1 | 出售中 1 | 已下架 0`，仅剩一个商品总数。

### DUP-02 手机端首页“待处理订单”显示两次

- 页面：商家后台手机端 → 首页。
- 原因：顶部统计卡与“待办事项”列表首行都渲染 `orderActionCount`。
- 修复：移除待办列表中的“待处理订单”行；顶部统计卡保留唯一数字，底部订单标签徽标仅在有待办时作为导航提示。
- 验证：首页文本中“待处理订单”只出现一次；待办列表保留低库存、待审核客户、生产运营。

### DUP-03 手机端客户页客户数显示两次

- 页面：商家后台手机端 → 客户。
- 原因：顶部“客户数”卡与“客户列表”标题右侧同时渲染 `filteredMerchantCustomers.length`。
- 修复：保留顶部统计卡，移除标题右侧重复计数。

### DUP-04 Web 首页商品入口重复

- 页面：商家后台 Web → 经营主页。
- 原因：“常用功能”中的“全部商品”、近期商品的“查看全部”、侧栏“商品列表”指向同一商品目录。
- 修复：“常用功能”改为“客户管理”；商品目录保留侧栏主入口与近期商品上下文入口“查看全部”。

### DUP-05 Web 首页隐藏的旧版重复面板

- 页面：商家后台 Web → 经营主页。
- 原因：`<div className="hidden">` 内仍保留旧版“经营数据 / 销售趋势 / 补货清单 / 待办事项 / 热销排行 / 仓库现货”整组重复面板，虽不可见但会打包、维护并造成第二套口径。
- 修复：删除整段隐藏旧版面板；当前首页只保留现行统计、近期商品、待办与经营分析折叠区。

### DUP-06 Web 导航“库存管理”同名两次

- 页面：商家后台 Web → 侧栏“商品库存”展开区、“更多”菜单。
- 修复前文本：`库存管理` 分组标题下只有 `库存管理` 菜单项。
- 修复：分组标题改为“库存台账”，菜单项仍为“库存管理”；同一导航层级不再出现同名标题与入口。

### DUP-07 Web 导航中的商品总数与商品页总数重复

- 页面：商家后台 Web → 侧栏、顶部标签、商品页。
- 原因：侧栏“商品库存”徽标和顶部“商品管理 (N)”同时显示商品总数，商品页筛选胶囊“全部 N”再显示一次。
- 修复：移除侧栏徽标与顶部标签中的商品计数；商品总数只在商品页“全部 N”出现。

### DUP-08 Web 客户页可见客户数重复

- 页面：商家后台 Web → 客户管理。
- 原因：无筛选时筛选摘要“符合 1 / 1 位”与列表头“1 位客户”同时出现。
- 修复：筛选摘要仅在存在搜索/状态/国家/分群/订单条件时显示；默认状态只保留列表头计数。

### DUP-09 Web 商品页重复的单项二级导航

- 页面：商家后台 Web → 商品。
- 原因：商品页顶部只有“店铺分类”一个按钮的二级导航，与侧栏“店铺分类”完全重复。
- 修复：移除该单项导航条；店铺分类继续由侧栏唯一入口进入。

### DUP-10 生产链概览数字重复

- 页面：商家后台 → 智能生产链 → 概览。
- 原因：“待确认对账”统计卡与“对账”标签页徽标同时显示 `pendingStatements`；“加工单”徽标同理。
- 修复：概览标签页不显示数字徽标，进入加工单/对账标签页后再显示，避免同屏重复。

### DUP-11 侧栏无意义零徽标

- 页面：商家后台 Web → 侧栏“生产采购”。
- 原因：“生产工单”始终渲染数量徽标，空数据时显示 `0`，与“库存台账”等入口的干净状态不一致。
- 修复：仅在未完成工单数大于 0 时显示徽标；为 0 时不渲染。

### DUP-12 手机端空数据重复 `0`

- 页面：商家后台手机端 → 首页待办、生产运营。
- 原因：低库存与待审核客户都为 0 时仍渲染两行 `0`；生产运营显示 `0 物料预警 · 0 工单`。
- 修复：待办行仅在数量大于 0 时显示，全为 0 时显示“暂无待办”；生产运营摘要改为“暂无生产预警”。

## 4. 数据来源与计算口径核查（针对“不能只隐藏数字”）

本轮逐个确认了商品数量与库存数量的来源，未发现为了显示而二次计算或重复累计：

1. 客户端商品集合只有一个来源：
   - 手机端：`const merchantProducts = products.filter(p => p.merchantId === currentMerchantId)`；商品页、首页、筛选胶囊全部读取该集合。
   - Web 端：`const merchantProducts = serverProducts ?? products.filter(p => p.merchantId === currentMerchantId)`；侧栏、首页、商品页共用该集合。
2. 服务端只有一个商品列表接口：`GET /api/merchant/products` 使用单次 `prisma.product.findMany({ where: { merchantId } })`，响应中的 `count` 由同一 `products` 数组长度生成，不存在第二个统计接口或独立 `COUNT(*)`。
3. 数据库只有一张商品主表 `Product`；商家隔离由 `merchantId` 条件完成。没有按商家重复写入商品汇总表。
4. “商品数量”与“现货数量”含义不同，未合并：
   - 商品数量 = 商品行数（款数）。
   - 现货 / SKU 现货 = `InventoryBalance.onHandQuantity` 按 SKU 汇总；不会加进商品款数。
5. 本轮修复只删除重复渲染位置，没有保留“隐藏但仍在计算”的第二套商品总数；唯一保留的商品总数是商品页“全部 N”胶囊，其值直接来自 `merchantProducts.length`。
6. 本轮未修改 API、数据库 schema、迁移或权限；不存在为清理 UI 而改变业务数据的情况。

## 7. 发布状态与风险

- 本轮代码改动仅本地，未执行 `publish:app`、未部署、未迁移生产数据库、未修改生产配置。
- 生产发布前需要用户明确授权；发布后需按本文件第 5 节重新做真实生产会话截图（尤其是手机端商品、首页、客户页与 Web 商品页）。
- 回滚方式：本轮为前端渲染层与测试/文档改动，无数据库迁移；回滚对应应用 release 即可。
- 风险：`tsc` 全仓 OOM 仍在；后续改动应继续以构建 + Playwright 运行时错误监控作为最低门禁，并尽快补齐可执行的分应用类型检查。

## 8. 后续建议（按优先级）

1. 为平台总后台、前台、小程序、员工端分别建立同一套“重复数字 / 重复入口”检查清单并补截图。
2. 把 `tests/duplication-guards.test.ts` 扩展为按模块的静态规则，但只固定已确认的事实，避免误报。
3. 统一通知未读数的唯一来源与跨端去重键，验证同一事件不会在 Web、手机端、小程序各创建一条消息。
4. 修复全仓 `tsc` 内存问题，恢复类型检查门禁。
