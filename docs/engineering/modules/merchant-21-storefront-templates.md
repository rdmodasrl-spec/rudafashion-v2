## 1. 现状清单

### 1.1 渲染入口与组件树

| 层 | 事实 |
| --- | --- |
| 入口 | `src/apps/frontend-web/main.tsx` → `PublicFrontendApp` → `MerchantStoreView` |
| 店铺页组件 | `src/apps/shared/components/frontend/MerchantStoreView.tsx`（**1 037 行，唯一实现**） |
| 样式 | `MerchantStoreView.css`（**158 行，100% 是颜色/边框/圆角/阴影覆盖**） |
| 模板注册表 | `src/shared/merchantStorefrontTemplate.ts`（3 个 id） |
| 域名 | `https://<storeSlug>.ruda.fashion/<lang>/`（`src/shared/merchantStoreUrl.ts`） |
| 复用方 | `frontend-web` 与 `frontend-mobile` 共用同一组件（无独立移动实现） |

**核心结论**：现有「三套模板」= 同一份页面的三套配色皮肤。`MerchantStoreView.tsx` 中 `storefrontTemplate ===` 出现 **0 次**；模板只以 `data-storefront-template` 属性出现（第 337 行，1 处）。因此 21 套目标**无法**通过继续追加 CSS 覆盖实现。

### 1.2 现有页面结构（所有模板共用）

```
header（居中品牌名 + 联系方式）
sticky nav（全部 / 特价 / 授权订做区 + 购物车）
hero（全幅视频，58–72vh）
profile（品牌简介）
products（单一网格，商品卡：图 / 名 / 价 / 库存 / MOQ / 加购）
footer
```

- 商品详情：点击商品卡后打开**浮层**（`selectedStoreProduct` 状态），**没有独立详情页**。
- 站内搜索、筛选、排序、分页：**均无**。
- 分类：只有 3 个商品桶（new / clearance / custom），**没有商家自定义分类导航**。

### 1.3 数据来源与授权（沿用，不得改）

| 项 | 现状 |
| --- | --- |
| 商品/商家数据 | 来自 `B2BContext`（前端已加载的 products / merchants），按 `merchantId` 过滤 |
| 授权过滤 | `canViewWholesaleProducts`、`isVaultApproved`、`isLockedForBuyer`、`visibility`（wholesale/private）、`isExclusiveProtected`、`lifecycleStatus` |
| 价格 | `calculateCustomerPrice`（按买家折扣率），未认证买家按原价规则 |
| 库存 | SKU 级 `stockCentral` / `getAvailableStock` |
| AI 客服 | `/api/merchant-ai/support/status/:merchantId` |
| 品牌资料 | 商家设置（logo/banner/showroom 图/视频/简介/SEO/配送与退换政策） |
| 模板持久化 | 写入商家 `settings.storefrontTemplate`（`withMerchantStorefrontTemplate`），服务端校验 `isMerchantStorefrontTemplate`，非法值返回 `STOREFRONT_TEMPLATE_INVALID` |

## 6. 开发风险

| 风险 | 说明 | 控制 |
| --- | --- | --- |
| 21 份复制 | 最容易发生的失败模式 | 模板注册表 + 3 种布局骨架 + 行业内容块；禁止复制整页组件 |
| 切换丢数据 | 模板只改 `settings.storefrontTemplate` | 发布前校验 + 保存快照 + 一键回滚；切换只改展示层 |
| 授权泄漏 | 新模板可能绕过现有过滤 | 过滤逻辑集中在数据装配层，模板只能拿已过滤结果；阶段 D 专项验收 |
| 强调色外溢 | 黑金/商城蓝进入全局 | `data-storefront-template` 作用域 + 机械检查 |
| 与项目一提交混杂 | 商家端选择器位于后台 | 选择器改动单独提交、单独验收，不改后台外壳 |
| 前台框架被重构 | 擅自换栈 | 阶段 A–D 不动 React/Tailwind 版本 |
| 假数据冒充 | 无门店/无采购分析却做展示 | 只用真实接口；无数据即空状态 |
| 手机端只做缩小 | 交付质量不达标 | 每套模板必须给 390 布局图与截图 |

### 10.3 每套模板的证据包

证据存放在 `docs/engineering/evidence/storefront/<批次>/<template-id>/`，每套至少包括：

1. `manifest.md`：提交 SHA、构建目标与 release ID、测试环境起点 URL、商家/行业/模板 ID、测试身份类别、精确执行命令、日期与结果。
2. 截图：真实渲染的首页、目录/搜索结果、商品详情、购物车或询价状态；1440×1000、820×1180、390×844。截图须来自同一个商家和同一组真实商品，不得用 mock 填充冒充交付。
3. 交互记录：模板配置保存并刷新后仍生效；导航、筛选、排序、详情深链/刷新、加购/询价等该模板实际支持的主流程。
4. 网络与控制台：请求失败、HTTP 状态和 console 错误原文；授权商品使用未授权/已授权身份核验列表、详情、图片、价格、SKU、库存与媒体 URL。
5. 评分表：按本文 §8 分项评分；任一一票否决项直接不通过，不允许平均分覆盖安全/交易失败。

证据不得包含凭证、访问令牌或不必要的个人数据。真实商家数据只用预先批准的测试商家；生产环境不得执行写操作。

### 10.4 完成与不合格标准

一套模板标记“已完成”必须同时满足：

- 通过真实商家正式店铺路由渲染，按服务端行业限制提供，选择和发布状态可持久化；不只是预览组件。
- DOM/导航/详情/移动交互有本模板自己的结构，且与同业另两套可验证地不同。
- 所有商品、价格、库存、媒体、商家联系信息来自既有权威 API/数据；授权只在服务端和唯一数据装配层实施。
- 页面上所有可见操作都有真实结果；失败状态明确；无虚构业务字段、交易成功或资源。
- 桌面/平板/手机有真实截图和流程记录；390px 无横向溢出；没有裂图、console error 或未解释的失败请求。
- 评分 ≥90/100，且没有一票否决项。

以下任一情况即不合格：只在实验室/隔离预览出现；仅改颜色/图片/标题；使用演示种子数据冒充真实商家数据；绕过授权过滤；按钮无业务结果；服装既有功能回归；缺任一目标视口证据；评分低于 90；没有提交证据清单。状态必须写“待验证”或“被阻塞”，不得称已完成。

### 10.5 正式店铺配置契约（实现前约束）

- 复用现有 `settings.storefrontTemplate`、商家模板保存 API 和 `MerchantStorefrontTemplate` 类型；不建第二个配置字段或发布系统。
- 既有三个 legacy ID 保持可读、可渲染、可回滚；不批量改写既有商家设置。新增 21 个结构型 ID 只允许在其所属行业配置。
- 服务端必须根据认证商家数据库记录读取行业并验证模板归属；禁止信任请求体的 `industry`、`merchantId` 或前端过滤。行业不匹配返回现有结构化验证错误，不写设置。
- 模板保存沿用当前商家租户认证和 API 错误格式；成功后返回服务端持久化模板值。公开店铺刷新必须按该权威值路由到结构模板。
- `GET /api/merchant/settings` 在认证商家资料中返回 `storefrontTemplateOptions`：选项由服务端数据库行业计算，包含当前已选的 legacy 模板以便旧店铺安全保留；小程序不得自建第二份行业映射。该列表只用于呈现，保存仍由 `PUT /api/merchant/storefront` 按数据库行业重新校验。
- 正式页面不得调用 `StorefrontPreview`（其模板选择器、noindex 和 query merchant 是隔离预览语义）；应复用模板组件与数据装配，但正式站点 URL、SEO、历史路由、登录/授权和交易边界必须由正式店铺入口持有。
- 发布前必须加测试：七行业有效 ID 全部可保存/读回；跨行业模板拒绝且不变更设置；旧 ID 仍可读取；匿名/未授权不得访问仅预览模板切换入口。

### 10.6 正式路由接入进度

- `MerchantStoreView` 已按服务端返回的模板 ID 分流：legacy ID 仍走原页面，结构型 ID 动态加载正式结构模板；店铺/模板变化会重置详情状态。
- Web 与手机 Web 选择器按行业展示三套结构型模板；`PUT /api/merchant/storefront` 从数据库读取行业并拒绝跨行业模板。
- `GET /api/merchant/settings` 向商家小程序返回服务端计算的模板选项；小程序不再因未知模板静默改写为 legacy ID，未知项只保留并禁止重新应用。
- 21 个结构型模板已登记唯一组件映射，并按行业拆分动态加载；店铺商品数据仍经过 `useStorefrontData`，不改商品授权规则。加载错误现在有显式状态。
- 以上为代码接入记录，不代表商家登录态的跨端保存、真实正式店铺浏览器、交易、响应式、3D 或 90 分视觉验收已通过。相应证据包尚未齐备，P2-01 仍为**部分完成/待验证**。
