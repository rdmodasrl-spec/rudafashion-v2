# Frontend Design（RUDA 适配版）

Adapted from Anthropic's `frontend-design` skill (Apache-2.0). Upstream asks the model to act as a design lead inventing a distinct identity per client. **RUDA already has an identity and it is not up for renegotiation.** This adaptation keeps the judgement and the critique vocabulary, and removes the "invent a new visual world" mandate.

## RUDA 覆盖规则（优先级最高）

1. `AGENTS.md`（铁规）> `docs/engineering/design-values.md`（令牌唯一权威）> 模块文档 > 现有代码 > 本技能。
2. **品牌固定**：字体栈、中性色阶、单一强调色 `#201e1a`、圆角令牌、`lucide-react` 图标全部已定。不得因为"要有独特视觉"而更换。
3. **结构固定**：不重排首页分区、不替换后台外壳、不动导航层级与 AI 助手栏（§15.5）。
4. **本技能的产出是判断，不是新方案**：用在「这里到底哪里显得廉价」以及「这个改法是不是在制造新模板」。
5. 只约束本次新写或修改的代码；历史写法不批量清理。

## 用在哪里

| 场景 | 用法 |
| --- | --- |
| 新建页面/区块 | 先用 `landing-page-design` Part A 定结构与文案，再用本技能校验视觉取舍 |
| 改造既有页面 | 先用 `redesign-existing-projects` 诊断，本技能判断某条修复是否值得做 |
| 评审 | 按下面的「模板化痕迹」清单逐项对照，输出问题而不是重写样稿 |
| 拒改 | 页面已经合格时明确说"不动"，并说明理由 |

## 需要警惕的模板痕迹（RUDA 语境版）

以下都是"默认值"而不是"选择"。出现时先问：这是为这个页面做的决定，还是顺手就成这样了？

1. **暖米色底 + 高对比衬线 + 砖红强调色**。RUDA 的暖中性灰是既定的，但强调色只有 `#201e1a`；新增砖红/赤陶/金色一律视为跑偏。
2. **近黑底 + 单一荧光强调**。RUDA 没有深色主题。
3. **每个分区都是等宽卡片 + 同一个圆角 + 同一层灰阴影**。卡片只在需要表达层级时存在；圆角必须用 `--radius-ruda-*`。
4. **每个标题上方都加全大写小字标签（eyebrow）**；中文界面里变成「· 分隔符 · 拼起来的元信息」。除非该信息真的需要分组，否则删掉。
5. **用 `01 / 02 / 03` 编号装饰并不存在的顺序**。只有真流程（下单三步、入驻审核）才配编号。
6. **同一屏出现多个同等重量的按钮**。一个主操作。
7. **每张卡都 hover 上浮 + 淡入**。这类"到处都在动"是典型的生成感；见 B7 动效规则。
8. **标题里单独把某个词换色/斜体/加粗来"强调"**。用字号与字重建立层级。
9. **为了"高级"而全部缩小字号**。RUDA 的底线是正文与标签 ≥12px。
10. **空状态只有一句"暂无数据"**。空状态是引导，不是占位。

## 首屏判断

首屏要回答三件事中的至少两件：这是什么、给谁、下一步做什么。

- 买家侧：允许全幅影像，但必须有文字层与主操作。**只有图 + 导航 = 未完成**。
- 商家/平台后台：首屏是"今天要处理什么"，不是营销位；操作入口优先于修饰。
- 不得用"大数字 + 小标签 + 渐变强调"这一套默认组合冒充设计。

## 排版判断

- 行宽：拉丁文案 <80 字符；中文 30–40 字。
- 层级靠字号 + 字重 + 间距三层建立，不靠颜色堆叠。
- 数字界面（价格、库存、数量）启用 `tabular-nums`。
- 衬线体只用于买家侧展示；后台一律 sans。
- 标题断行按语义断，不按字数断；避免末行孤字（`text-wrap: balance` / `pretty`）。

## 结构装置

边框、分割线、编号、眉标、标签只有在**编码信息**时才使用。纯装饰性的横线、竖线、角标一律删。

## 动效

- 一次页面只安排一个入场序列，不要每个分区都淡入上浮。
- 用户动作触发的反馈（展开、确认、切换）比自动播放的装饰动画更值得投入。
- 只用 `cubic-bezier(0.22, 1, 0.36, 1)`；只动 `transform` / `opacity`；必须处理 `prefers-reduced-motion`。

## 文案

- 从使用者视角命名：写"通知设置"，不写"webhook 配置"。
- 主动语态；按钮说的是会发生的事（"保存修改"，不是"提交"）。
- 同一动作全流程同名：按钮写"发布"，提示就写"已发布"。
- 错误说清"哪里失败 + 下一步"；空状态给出可执行的下一步；不道歉、不用感叹号。
- 中文禁空话：「赋能」「一站式解决方案」「极致体验」「颠覆」「重新定义」。

## 工作方式：先计划，再自评，再动手

1. **读现状**：目标页面、相邻页面、令牌、已有组件。
2. **写一句主张**：这个页面要让人第一眼记住的一件事是什么。写不出来就先别改。
3. **对照上面的清单自评**：计划中的每一项，是"为这个页面做的决定"还是"默认值"。
4. **小步实现**：一次一个区块，可审查 diff。
5. **自评产出**：改完按「模板痕迹」再看一遍，删掉自己刚加进去的装饰。
6. **验证**：1440 / 820 / 390 三档真实截图 + `impeccable detect`。

## 不该做的事

- 不建议更换字体、配色、圆角体系、图标库。
- 不为了"更有设计感"新增板块、插画、装饰图形。
- 不在既有页面里引入新的动效库。
- 不把"和上游示例不一样"当成缺陷。
