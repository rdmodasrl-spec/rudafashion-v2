# RUDA Merchant 手机版商品页开发记录

## 目标与范围

手机版商品页是服装商家的商品目录工作流，主要动作是：**找商品、查看并发送商品、上传或维护商品**。列表负责快速找款和看价/件数，详情负责完整查看与分享，新增及编辑继续复用现有商品表单与业务接口。

本记录只涉及 RUDA Merchant 手机版商品列表、商品详情、分享面板及其权限表现。首页设计、桌面端菜单和布局、数据库结构不属于本功能范围。

## 商品列表

- 内容区不重复标题说明文字；固定头部只保留“商品”标题和一个“上传商品”按钮，不放大段介绍。
- 商品页隐藏与找款无关的全局未开店横幅和账号角标，避免在商品列表首屏占位；账号设置仍可从其他页面进入。
- 商品为空或筛选无结果时使用紧凑文字状态，不展示大图标/大面积空卡片。
- 头部固定四行：标题与上传、搜索、快捷筛选（商品 / 低库存 / 新款 / 已售出）、业务分区（现货 / 折扣 / 授权）；列表在固定区下方独立滚动。
- 搜索商品名称、款号和 SKU；沿用当前商品列表数据，不新增商品查询 API。
- 快捷筛选与业务分区是两层独立控件，按“与”叠加：分区决定归属范围，快捷筛选在该范围内收窄。商品入口显示当前权限范围内全部商品数；低库存、新款、已售出分别显示对应真实商品数。
- 使用纵向卡片，不使用手机端宽表格。卡片展示主图、名称、款号、批发价、已配置的阶梯价、SKU 可售总数、颜色/尺码数量和上架状态。
- 卡片可打开详情、发送给客户、进入编辑，以及在卡片操作菜单中复制、上架/下架或归档。
- 商品成品可售数量按 SKU 汇总 `stockCentral - reserved`，并将负数归零；物料库存仍由库存模块管理。
- 不在手机商品页头部放置更多图标；CSV 导入/导出继续使用已有桌面商品工作台，不在手机端另造导入流程或占用商品页头部。
- 空商品状态保留说明，不重复放置第二个添加商品按钮；新增入口统一使用顶部按钮。

## 快捷筛选与已售出口径

搜索框下方四个快捷入口都是可点击的真实筛选，不是装饰文字；样式为等宽四列、线性黑白图标 + 标签 + 真实数量。

| 入口 | 筛选值 | 数据来源与口径 |
|---|---|---|
| 商品 | `all` | 当前商家权限范围内的全部商品，数量为商品集合长度 |
| 低库存 | `low_stock` | `isLowStockProduct`：SKU 在手库存合计 < `PRODUCT_LOW_STOCK_THRESHOLD`（20），与商家 Web 同口径 |
| 新款 | `new_arrival` | 商品 `createdAt` 在最近 30 天内（`MERCHANT_NEW_ARRIVAL_WINDOW_DAYS`） |
| 已售出 | `sold` | 真实订单成交明细的净售出件数 > 0 的商品；列表行显示该商品累计净售出件数 |

「已售出」数据契约（2026-10-26）：

- 接口：`GET /api/merchant/products/sales-summary`，`requireMerchantTenant`，权限与商品列表一致（`sales.order.create` / `production.report` / `product.publish` 任一）。
- 响应：`{ success: true, count, totalSoldUnits, products: [{ productId, soldUnits, orderCount, lastSoldAt }] }`；`soldUnits` 为净件数，`orderCount` 为包含该商品的有效订单数，`lastSoldAt` 为该商品最近成交订单时间。
- 数据来源只有 `OrderItem`（成交明细）和 `ReturnRequest`（退货明细），不新建统计表、缓存或第二份商品数据，也不使用 `inventoryStatus` 文本。
- 计入规则：排除 `draft`、`cancelled`；排除整单退款（`paymentStatus=refunded` 或 `refundStatus=completed`）；扣减状态为 `received` / `refunded` 的退货明细件数（按订单 + 商品 + SKU 封顶，结果不为负）。仅提交或仅批准的退货仍按已售出计。
- 「已售出」不等于「已售罄」：列表只看成交记录，不看当前库存；有库存的商品可以出现在已售出列表，库存为 0 但从未成交的商品不会出现。
- 前端进入商品页时读取一次汇总；未读取完成时入口数量显示 `—`，不显示 0 或假数字；读取失败可点击入口重试，并通过既有通知反馈。
- 规则实现：`src/shared/merchantProductSales.ts`（共享类型与索引）、`src/server/merchantProductSales.ts`（`summarizeMerchantProductSales`）、`src/shared/merchantProductBrowse.ts`（快捷筛选与分区过滤）。
- 单测：`tests/merchant-product-sales.test.ts`、`tests/merchant-product-browse.test.ts`。

## 商品详情

点击商品卡片打开手机版详情面板。详情使用商品真实资料，包含主图及可选图片、名称、款号、状态、价格、起订量、可售总数、颜色/尺码、SKU 库存明细，以及已有的商品描述、面料、成分、版型和工艺信息。

SKU 明细默认最多显示 6 条，规格较多时可展开剩余规格。SKU 库存数量按现有库存字段扣除预留量计算。编辑表单可调整有权限维护的商品及 SKU 资料；库存数量继续通过现有库存业务管理。

详情底部提供“发送整个商品”和“编辑商品”两个分开的操作，分别用于客户分享和商家维护。

## 分享商品

- 分享地址使用商家店铺来源域名和现有商品详情路径 `/product/:id`，不新建公开商品 API。
- 草稿不可分享；店铺标识或商品链接不可用时显示错误提示。
- 面板提供复制链接、WhatsApp、电子邮件；浏览器支持 `navigator.share` 时也提供系统分享，否则系统分享回退为复制链接。
- 分享消息仅包含商品名称、款号和店铺链接，不把批发价格直接写进消息。客户访问链接后，商品价格、私密商品和规格信息继续遵循现有店铺展示、客户授权及商品权限规则。
- 仅呈现已接通的分享渠道；复制或分享失败时通过现有通知反馈错误。

## 编辑权限和新增商品

- 商品权限从现有 `GET /api/merchant/products` 响应读取。商家所有者可管理商品；员工需要现有 `product.publish` 权限。前端等待权限核验时禁用编辑入口，无权限时提示联系店铺管理员。
- 卡片锁图标只代表浏览/编辑状态，不代表商品上架状态。点击锁图标进入对应商品的编辑流程；编辑中显示解锁状态。保存、取消或关闭后恢复锁定。取消有未保存更改时先确认。
- 商品资料更新沿用现有 `PUT /api/merchant/products/:id` 及 `updateProduct`；服务端仍执行租户范围和权限校验。
- 新增商品沿用既有商品创建表单，支持现有的图片、基础资料、颜色/尺码/SKU、批发价、起订量及草稿/发布工作流，不创建新表或重复业务接口。
- 复制商品进入现有创建表单；复制品 SKU 编号使用 `-COPY` 后缀，初始库存归零，避免复制原商品库存。

## 代码位置

- `src/apps/merchant-admin-mobile/MerchantMobileApp.tsx`：商品列表、筛选、详情、分享面板、编辑入口及现有创建/编辑表单编排。
- `src/shared/merchantProductBrowse.ts`、`src/shared/merchantProductSales.ts`：快捷筛选、分区与已售出索引的共享规则和类型。
- `src/server/merchantProductSales.ts`：已售出净件数汇总（订单成交明细与退货明细）。
- `server.ts`：商家商品列表与新增 `GET /api/merchant/products/sales-summary`；商品更新路由保持原样。
- `src/i18n/uiCopyCatalog.ts`：手机版商品页中意文案目录。
- `src/apps/merchant-admin-web/MerchantPortal.tsx`：已有桌面商品工作台及 CSV 工具，本次不调整其布局。
- `src/apps/shared/components/frontend/ProductDetailView.tsx`、`src/utils/share.ts`：现有商品详情路径及共享路由工具。

## 维护约束与验收

后续调整商品页时应保持以下约束：

1. 商品列表继续适配窄屏，不引入横向宽表格或重复库存管理入口。
2. 价格、SKU、状态、库存和已售出件数必须来自当前商家真实数据；不得添加演示商品或伪造统计值。
3. 所有读写继续使用现有租户隔离、员工权限和买家商品授权逻辑。
4. 分享链接不应绕过私密商品访问控制或向无权客户泄露批发价格。
5. 编辑商品资料与维护成品库存保持为两个既有业务边界。
6. 保持桌面端布局、数据库结构及首页不变。
7. 验证翻译文案覆盖、TypeScript 检查及生产构建；在 320–430px 宽度检查列表卡片、快捷入口、详情和分享面板，避免横向溢出。
