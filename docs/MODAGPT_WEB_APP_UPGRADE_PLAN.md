# 商家端 ModaGPT / AI 服装创作工作室升级计划

版本：1.0  
制定日期：2026-10-18  
适用端：Web 商家后台、商家 App / 移动端 ModaGPT  
产品范围：AI 智能服装设计师、AI 真人虚拟试衣、AI 商业模特工作室、AI 服装精准换色、AI 秀场视频制作

## 1. 目标与产品决策

在现有 RUDA 商家系统内，把分散的 ModaGPT 创作能力升级成商家可持续使用的五个专业工作区。Web 商家后台增加独立的「AI 服装创作工作室」目录；App 保持当前 ModaGPT 首页、入口和首页视觉不变，只在用户进入 ModaGPT 后增加五个子工作区及返回路径。

### 集成方式：原生集成，不把 MODAGPT 作为运行时插件

旧的 `MODAGPT/` 独立 Vite/Express 原型已清理。不要恢复第二套服务端、登录、商家租户、存储、任务、额度或审计边界；本计划仅保留其架构风险结论，实际功能以 RUDA 主应用为准。

因此：

- RUDA 主应用继续作为唯一生产运行时、认证入口、租户边界、计费和资产来源。
- MODAGPT 目录用作交互参考、算法/引擎原型和质量测试思路；每项代码在复用前必须核对依赖、许可证、数据流和安全边界。
- 迁入的能力改为调用主应用的商家 API、私有素材存储、ModaGPT 权益和任务/审计体系。
- 不复制演示图片或本地 Mock 结果作为生产结果；未接入真实服务的功能明确显示为未开放。

### 工程原则：能力稳定，模型可替换

这次先把五项工作流、资产关系、质量验收和计费/任务边界做扎实，不因追逐新模型而并行接入多个供应商。后续新增模型时，应能通过服务端适配器接入，不要求重做商家页面、作品库或计费系统。

- 每个创作任务使用平台定义的输入/输出契约；供应商专属字段、凭证和错误只存在于服务端适配器。
- 按任务类型声明并校验能力，例如参考图、蒙版、身份参考、画幅、时长、异步任务和局部编辑。能力不支持时禁用相应控制，不以提示词伪装支持。
- 先保留当前生产适配器。新适配器必须通过相同服装样本、质量基准、错误/超时、成本和授权检查后，才可配置为生产或备用；不做未经验证的自动切换或可能重复计费的盲目重试。
- 记录任务实际使用的供应商、模型版本、参数、输入资产版本、耗时、结算和质量审核结果，便于复现与回归。
- 用户界面依赖 ModaGPT 能力，不依赖供应商名称；必要的数据外发和肖像授权提示仍须清楚说明。

## 2. 当前代码基线

以下为制定计划时从代码确认的现状，不代表端到端生产验收已经完成。

| 能力 | 当前实现 | 主要缺口 |
|---|---|---|
| 商家 Web | `MerchantPortal.tsx` 有独立 Web 商家导航与页面渲染 | 已补五项创作目录；设计、试衣、模特复用现有 ModaGPT，本地换色已接入；秀场视频仍待真实服务 |
| 商家 App / 移动端 | `MerchantMobileApp.tsx` 承载移动端；`MerchantAiHome.tsx` 是 ModaGPT 创作界面 | 用户要求首页保持不变；新增能力应放在首页之后的子工作区 |

| 秀场视频 | 主应用其他场景有视频编辑/导出基础；MODAGPT 原型有视频工作流代码 | 不能等同于商家端 AI 视频生成；尚未确认商家 API、真实模型提供方和完整任务链 |

## 3. 产品信息架构

### 3.1 Web 商家后台

增加一级导航「AI 服装创作工作室」，进入独立的桌面/响应式工作区：

1. 工作室目录
2. AI 智能服装设计师
3. AI 真人虚拟试衣
4. AI 商业模特工作室
5. AI 服装精准换色
6. AI 秀场视频制作
7. 我的创作项目 / 资产 / 任务（按后续阶段开放）

每个子工作区使用统一的项目上下文和返回目录操作，不另造一套商家身份或作品存储。

### 3.2 商家 App / 移动端

- 不更改当前商家 ModaGPT 首页、首页卡片布局、首页默认 tab 和手机商家主导航。
- 从现有 ModaGPT 首页进入「创作工作室」后，再显示五个子工作区。
- 子工作区支持返回 ModaGPT 首页、返回上一个工作区，以及中断后恢复输入/任务状态。
- 设计、试衣等现有入口可以通过工作区深链预选功能，但不能让新入口改变原有首页默认行为。

## 4. 分阶段实施路线

按依赖顺序推进；每一阶段通过验收后再开始依赖它的阶段。具体日期不预估，避免在模型、凭证和质量基线未确认前承诺虚假工期。

### 阶段 0：现状审计与质量基准

**工作**

- 逐项检查主应用及 MODAGPT 原型的实际实现、请求/响应、存储、权限、许可和测试。
- 为五项能力标记：生产可用、部分可用、仅原型、未接入；验证实际模型调用，不依据 UI 文案推断能力。
- 建立经授权的服装、模特、颜色和场景测试集；记录原图、提示词、模型/版本、输出和人工评审结果。
- 确认 Fal/其他真实图像与视频服务配置、额度、成本、数据保留及外发告知要求；无凭证或预算时只做非计费验证。

**交付与验收**

- 差距矩阵列出页面、API、数据库、权限、费用、测试和剩余风险。
- 固定基线测试可重复运行；禁止硬编码质量分、静态图冒充生成结果或把失败标成成功。

### 阶段 1：双端目录与工作区骨架

**工作**

- Web 商家后台新增独立工作室入口、五项目录和各自工作区壳层。
- App 只在现有 ModaGPT 内增加子目录与工作区导航；保持首页和默认打开路径不变。
- 提取共享的工作区导航、上传/预览、任务状态和结果卡片等公共 UI；Web 与 App 可采用各自适配布局。
- 对不可用能力展示明确状态和原因，不展示假的「开始生成」结果。

**验收**

- 已登录商家可从 Web 和 App 分别进入工作室；越权/无商家身份时不能访问商家 API。
- App 首页截图/路由回归不变；从首页进入和返回工作区不丢失既有首页状态。
- 五个入口名称、描述、状态与本计划一致。

**当前实施记录**

- Web 商家导航新增「创作工作室」目录，列出五项目标能力及当前真实可用状态。
- 五项目录入口打开现有 `MerchantAiHome`；设计、试衣、模特使用现有商家 API，局部换色通过浏览器本地选区并保存至现有作品库。
- 设计师入口使用自然语言简报，要求 ModaGPT 返回三个可继续修改的方向；生成 2–4 张概念图时，图像提示词采用有差异的设计方向而非误用为同一设计的不同视角，并校验 800 字符服务端限制；未提供的成分/工艺需标记待确认。
- 商业模特工作区以自然语言描述模特、场景、灯光和摄影风格，可选候选数量；当前生成不读取商品参考图，也不保证不同候选中的模特或服装细节一致。
- 以上仍是基础工作流，不代表已经具备结构化设计规格、多图参考、数字人身份档案或专业质量验收；相应能力按后续阶段建设。
- 精准换色支持本机涂刷/橡皮擦、上一步撤销、清空选区、同一选区最多四种颜色候选、逐个对比/下载/保存；图片最长边缩放至 1600 px，像素换色分块让出浏览器主线程，失败时保留已完成候选。算法映射到目标色调，同时保留明暗层次和透明度，也支持黑/白等低饱和度目标色；未自动分割及需人工检查边缘的局限在界面提示。
- 重新生成会先确认替换当前对应颜色预览；重新选图会清除旧选区/撤销快照，生成或保存期间锁定冲突操作。
- 设计概念候选使用稳定的 4 方向提示词契约：忠于简报、差异廓形、极简经典、编辑表现；每张图仍为独立模型输出，不承诺跨图款式一致，也不替代结构化规格或量产审版。
- 秀场视频在主应用完成真实服务、任务和计费闭环前保持禁用并说明原因。
- 商家 App 首页及移动端路由未改；共用 `MerchantAiHome` 的创作流程同样呈现五项能力。
- 五项全量功能、异步任务恢复、双端真实模型质量和费用验收仍未完成；不能把当前目录与基础工作流视作最终交付。
- 当前换色/提示词/作品幂等回归验证：`node --import tsx --test tests/modagpt-design-idempotency.test.ts tests/garment-recolor.test.ts tests/modagpt-image-contract.test.ts tests/modagpt-entitlements.test.ts`（19 项通过）；`npm run build` 最近成功。此验证不代表真实模型生成、自动分割或专业视觉质量验收已经完成。
- 作品保存幂等 ID / 内容指纹已接入现有商家作品 API 与 Prisma 迁移；尚未在生产环境应用该迁移。幂等保障只覆盖客户端提供 ID 的新保存请求，历史或旧客户端请求保持兼容。

### 阶段 2：统一项目、资产、版本和任务基础

**工作**

- 设计商家租户隔离的数据关系：项目、功能类型、输入素材引用、生成任务、候选结果、版本、用户确认状态、模型/参数、用量/成本和审计记录。
- 复用现有商家 ModaGPT 设计记录、私有对象存储、额度/积分结算和现有任务设施；先核实既有表/队列再决定是否新增迁移。
- 作品保存接收可选客户端幂等 ID，按商家隔离并绑定标题、提示词、类别和图片内容摘要；同一请求重试返回已保存资产，复用 ID 但内容变化返回冲突。用数据库唯一约束处理并发重试，失败对象清理并尝试回放已提交记录；旧客户端不带 ID 的行为保持兼容。
- 建立平台拥有的任务契约和供应商适配器边界；功能页面只依赖任务能力，新增供应商不改变业务数据或 UI 契约。先接通现有配置，不要求本阶段并行采购/接入新模型。
- 长时间生成采用可查询任务状态、幂等键、失败可重试、取消/过期状态和页面刷新恢复。
- 保存时只存引用及安全元数据；原图/人物照按隐私和留存策略处理，不默认永久保存。

**验收**

- 每个项目、资产和任务都按认证会话的 merchantId 读写，不能从请求体指定或切换租户。
- 重试不重复扣费；成功、失败、释放额度和实际费用状态一致。
- 项目关闭、刷新和重新登录后可按权限恢复已保存结果；删除按保留规则清理元数据和对象。

### 阶段 3：服装设计师与高保真虚拟试衣

**AI 智能服装设计师**

- 自然语言简报形成结构化设计卡：品类、廓形、面料、颜色、细节、季节/场景和未确认假设。
- 支持获授权的参考图和明确的硬性约束；模型能力不足时不显示不生效的控制项。
- 多候选生成、并排比较、用户选定后继续修改；保存 prompt/设计规格/模型/结果版本关系。
- 明确区分概念图与生产技术文件；不得自动声称版型、尺码、面料成分已可投产。

**AI 真人虚拟试衣**

- 提供商品服装与人物照片的明确配对、输入质量检查、预览、授权/隐私确认和结果审核。
- 以服装细节保真为首要验收；按品类覆盖格纹、针织、刺绣、透明材质、长外套、褶皱和不同姿势。
- 支持失败定位、幂等提交、任务状态恢复和结果另存版本；原图仅按已告知目的处理并遵循留存/删除策略。
- 局部修复、多角度商品参考和高清输出仅在适配器声明支持且通过专项质量测试后开放。

**验收**

- 每个候选可追溯其设计/商品输入、提示词、模型和版本。
- 验收集中检查服装结构、颜色、图案/纹理、人物身份、姿态和边缘伪影，不只检查是否返回图片。
- 获授权的固定样本集覆盖常见与复杂衣物；失败样例加入回归集，质量未达基线时能力保持 beta/关闭。
- 若服务不支持参考图一致性或指定控制，UI 必须限制选项或说明，不作强保证。

### 阶段 4：精准换色与数字人工作室

**AI 商业模特工作室 / 数字人**

- 支持审核后可复用的商家人物档案、身份参考图、授权状态、姿势参考与服装/设计版本关联。
- 用已确认的商品/设计创建任务，配置模特、姿势、背景、光线和构图；模型不支持身份保持或商品参考图时必须明确降级。
- 允许生成多张候选并重做单张；检查跨图人物与服装细节，不把单次文生图称为可复用数字人。
- 3D 数字人与布料模拟作为可选后续路线，不作为首版工作流强制依赖；提供审核、选择、保存、下载与返回商品素材的闭环。

**AI 服装精准换色**

- 支持手动修正或经测试的服装/衣片分割掩膜，色彩处理需保留明暗、纹理、印花、纽扣和缝线。
- 提供 HEX 与可复用品牌色板、多个颜色变体、原图/结果同步比较、局部编辑与撤销版本。
- 量化评估使用适合的色差（如 ΔE00）、蒙版外变化、纹理保持与边缘溢色；指标结合固定图集和人工审核，不单独作为正确性证明。
- 原始商品图只读保留；非目标区域不变，未确认的区域不静默重绘。

**验收**

- 数字人档案与参考素材有明确授权及商家权限；保存、修改和删除均有审计和留存规则。
- 换色集验证目标颜色误差和衣物外溢；皮肤、背景、非目标衣物不得被误改。
- 质量结果由固定测试集和人工盲评记录支持；未达门槛时功能保持 beta/关闭。

### 阶段 5：AI 秀场视频制作

**工作**

- 仅允许从已确认的设计图/模特图创建视频任务；指定竖屏/横屏、时长和商业用途。
- 先选定可商用且配置完成的视频提供方，再实现队列、进度、失败/重试、取消、预览、确认、资产保存和费用记录。
- 支持结果版本、封面/比例预览和下载；供应商不支持的长度、人物一致性或镜头控制不得承诺。
- 与后台现有剪辑器明确区分：一个是商家 AI 视频生成，一个是后台视频剪辑/导出，不共用冒名状态。

**验收**

- 未配置真实视频供应方时页面说明不可用，不生成占位视频、不扣费。
- 任务刷新可恢复状态，供应商错误可定位，重复提交有幂等保护。
- 输出视频可解码、比例/时长符合选项，能关联回输入设计和商品素材。

### 阶段 6：商业化、质量治理与双端发布

**工作**

- 将五项能力统一纳入权益开关、额度/积分、实际供应商成本、审计、速率限制和异常告警。
- 增加人工质量评价入口及模型/提示词版本记录；检测图像安全、品牌授权和不应出现的文字/Logo。
- Web 与 App 分别做窄屏/桌面可用性、上传失败、弱网、刷新恢复、权限、额度不足和供应商错误回归。
- 对高成本/外部模型功能使用服务端 feature flag 分批启用；建立回滚开关。

**验收**

- 每项能力均有自动化测试、租户隔离测试、额度结算测试和失败路径测试。
- 真实模型测试仅在确认服务配置、用户授权和预算后执行；明确区分本地/Mock 测试与真实生成。
- 发布摘要记录代码提交、迁移、实际测试结果、已知风险和回滚方式。

## 6. 关键接口原则

- 继续使用 `/api/merchant/...` 的商家会话认证与 `requireMerchantTenant`，merchantId 只从服务端身份取得。
- 现有 `/api/merchant/modagpt/images` 先作为图像生成/试衣主入口评估；不新建绕开权益/额度/积分的平行接口。
- 新异步能力应返回 task id、状态和可轮询/恢复资源；提交需支持服务端幂等。
- 资产保存/读取沿用私有存储与商家隔离；浏览器不得获得对象存储长期公开 URL。
- 每种 task/feature 的请求、响应、错误码、状态迁移和计费语义需有共享类型与契约测试。
- 仅将已完成用户确认的候选保存为正式创作资产；中间结果使用明确的临时/草稿状态。

## 7. 质量与发布门槛

每个能力上线前必须提供：

1. 固定且获授权的测试素材集及可重复运行的测试命令。
2. 自动化功能、输入校验、错误处理、权限/租户隔离与额度测试。
3. 真实服务调用证据；若未调用真实模型，必须明确说明。
4. 人工盲评记录，覆盖服装关键结构、颜色、材质观感、人体/手部伪影、背景污染和文字/Logo 幻觉。
5. 延迟、失败率、单次供应商费用和重试成本记录。
6. Web、App 各自的窄屏/桌面或设备回归结果。
7. feature flag、迁移回滚和已知限制。

每项能力必须有自己的固定样本集、人工审核记录和失败样例回归；至少覆盖以下指标，不用一张演示图代替质量验收：

| 能力 | 质量检查重点 |
|---|---|
| 服装设计师 | 结构约束保留、设计规格字段完整、修改指令仅改变目标细节、概念图与量产文件区分 |
| 真人虚拟试衣 | 服装结构/图案/颜色保真、人物身份与姿态保持、复杂衣物表现、边缘和肢体伪影 |
| 商业模特 / 数字人 | 跨任务人物身份一致性、服装版本一致性、授权与参考帧追溯、单张重做不破坏其他候选 |
| 精准换色 | 目标色差、蒙版外像素变化、纹理/印花保留、边缘溢色；必要时结合 ΔE00 与人工审核 |
| AI 秀场视频 | 视频可解码、时长/画幅、动作自然度、人物与服装跨帧一致性、镜头单独重做能力 |

图片质量数值门槛应在阶段 0 建立基线后，与产品方共同确定；在基线和盲评结果未产生前，不填写伪精确分数或宣称「最高质量」。

## 8. 风险、依赖与边界

- Fal/图像模型和 AI 视频服务凭证、预算与商业许可未由本计划假定；缺少时继续开发无计费 UI、合同测试、任务/资产基础，不触发真实生成。
- 人物照片涉及隐私与肖像权；只有授权素材、明确同意、受控访问和既定留存策略才允许试衣。
- 生成服装概念不能替代纸样、尺寸表、面料检测或量产工艺审核。
- MODAGPT 原型本身不等于已接入 RUDA 租户、计费、隐私和生产存储；只能逐模块评估迁移。
- 项目当前存在多项未提交/已暂存的工作区变更。后续实施需先查看目标文件 diff，按增量方式集成，禁止覆盖或清理与本任务无关的修改。

## 9. 首个执行批次

1. 补全阶段 0 的五项能力代码/接口/权限/计费差距矩阵，并建立获授权的基准样本及质量评审流程。
2. 阶段 2 先落实商家隔离的共享资产/版本/任务契约和供应商适配器边界。
3. 按阶段 3–5 顺序升级设计与试衣、换色与数字人、最后接入秀场视频；每项仅开放已验证的能力。
4. 新模型以后按相同样本集做对照评估，通过质量、成本、延迟、授权和稳定性门槛后再接入；不因接入数量宣称质量提升。
5. 每阶段报告修改文件、测试命令与实际结果、真实生成是否执行、未完成项和下一阶段依赖。
