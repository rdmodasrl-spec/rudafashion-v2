## 1. 现状审计（代码事实）

### 1.1 当前"三套模板"的真实实现

| 事实 | 证据 |
| --- | --- |
| 模板注册表只有 3 个 id | `src/shared/merchantStorefrontTemplate.ts`：`fashion_monochrome`、`luxury_black_gold`、`ecommerce_standard` |
| 三套模板**共用同一份页面结构** | `MerchantStoreView.tsx` 中 `storefrontTemplate ===` 的出现次数 = **0**；模板只以 `data-storefront-template` 属性出现（1 处，第 337 行） |
| 三套差异**全部来自 CSS 皮肤** | `MerchantStoreView.css`（158 行）通篇是颜色、边框、圆角、阴影覆盖，没有任何布局或结构规则 |
| 店铺页是单一组件 | `MerchantStoreView.tsx`（1037 行）：header → sticky nav → hero video → profile → products → footer |
| 域名 | `https://<storeSlug>.ruda.fashion/<lang>/`（`src/shared/merchantStoreUrl.ts`） |
| 商家端切换入口 | Web `MerchantPortal.tsx:8049`、手机 `MerchantMobileApp.tsx:3897`，均为「一键应用到公开网店」 |

**结论：现有"三套模板"= 3 套配色皮肤，不是 3 套模板。** 21 套目标无法通过继续加 CSS 覆盖实现。

### 1.2 现有店铺页能力

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 品牌信息（名称/简介/Logo/联系方式） | ✅ | header + profile |
| 视频主视觉 | ✅ | hero 全幅视频（58–72vh） |
| 分类标签导航 | ✅ | 全部 / 特价 / 授权订做区 + 购物车 |

| 下单 / 加购 | ✅ | 复用买家购物车与订单 |
| AI 客服 | ✅ | 店铺内嵌对话 |
| 店铺 SEO（标题/描述） | ✅ | `storefrontSeoTitle/Description` |
| 响应式 | ⚠️ | 同一套断点（sm/md），无模板级移动布局 |
| 模板结构差异 | ❌ | **零** |

| 模板草稿/预览 | ❌ | 切换即影响线上，只能切完再去看 |
| 模板回滚 | ❌ | 无版本概念 |
| 模板级 SEO/OG | ❌ | 只有店铺级 |
| 模板级可访问性 | ⚠️ | 店铺导航 `text-[9px]/[10px]` 低于 12px 底线 |

### 1.3 已知缺陷（进入本项目时必须先修）

1. 店铺导航标签 9–10px（低于 `design-values.md` 的 12px 底线）。
2. 切换模板没有预览，商家只能"先改线上再看"。
3. 金色/蓝色强调色靠 CSS 覆盖实现，缺少作用域约束文档，存在外溢风险（已在 `brand-guidelines` 写明，但代码层无守卫）。

## 3. 架构提案（避免 21 份复制）

### 3.1 三层结构

```
模板注册表（industry → templateId[]）
        ↓
布局骨架（3 种结构，各行业复用）
   editorial ｜ catalog ｜ commerce
        ↓
行业内容块（该行业的数据映射与文案）
```

- **布局骨架只有 3 种**，但每套模板由「骨架 + 导航形态 + 首屏类型 + 商品展示形态 + 行业内容块」组合决定，因此 21 套外观与结构彼此不同，而代码不是 21 份。
- 禁止：为某个行业复制一份 `MerchantStoreView`；禁止改业务逻辑。

### 3.2 建议新增文件（实施阶段）

| 路径 | 作用 |
| --- | --- |
| `src/shared/storefrontTemplates/registry.ts` | `industry → [{ id, name, desc, layout, hero, nav, grid, accent }]` |
| `src/shared/storefrontTemplates/types.ts` | `StorefrontTemplateProps`（merchant / products / categories / cart / buyer 授权态） |
| `src/apps/shared/components/storefront/StorefrontEditorialLayout.tsx` | 编辑式：全幅影像 + 大字标题 + 双栏错落商品 |
| `src/apps/shared/components/storefront/StorefrontCatalogLayout.tsx` | 目录式：分类侧栏 + 密集网格 + 规格筛选 |
| `src/apps/shared/components/storefront/StorefrontCommerceLayout.tsx` | 商城式：促销位 + 商品卡网格 + 价格/起订/加购前置 |
| `src/apps/shared/components/storefront/industryBlocks/*` | 每行业的内容块（门店列表、贸易条款、箱包材质…） |
| `MerchantStoreView.tsx` | 保留为「入口 + 数据装配 + 分发」，不再承载三套皮肤实现 |

### 3.3 数据与授权契约（不新增、不复制）

- 商品/库存/价格：沿用现有买家侧 API 与 `calculateCustomerPrice`。
- 授权：未登录或未认证时按现有规则隐藏批发价与下单入口；模板只能改变**展示位置**，不得改变**可见性规则**。
- 域名：沿用 `<storeSlug>.ruda.fashion`，一套模板一份配置，不放宽租户隔离。
- 购物车/订单：沿用现有实现。

### 3.4 与项目一的边界

- 商家后台看到的「模板选择器」属于项目二的 UI（在 `MerchantPortal` / `MerchantMobileApp` 内），但**只允许改这块选择器**，不得顺带改后台外壳（§15.5）。
- 项目一改的是后台业务页面；项目二改的是店铺展示页。两者提交分开、验收分开。

### 3.5 视觉边界

- 每套模板可以在**店铺作用域内**有自己的强调色（如箱包奢品官网的金色、百货商城的蓝色），但：
  1. 只能通过 `data-storefront-template` 作用域生效，不得写入全局令牌；
  2. 不得进入后台或其他公开页；
  3. 字体、圆角令牌、图标库仍遵循 `design-values.md`；模板只允许改变布局密度与强调色。
- 这一条已写入 `.agents/skills/brand-guidelines/SKILL.md`，需要机械检查兜底。

## 4. 每套模板必须不同的四件事

1. **首页结构**：editorial（影像先行）/ catalog（目录先行）/ commerce（促销与价格先行）。
2. **商品展示**：双栏错落 / 密集网格 + 规格筛选 / 卡片化（价格、起订、加购同屏）。
3. **导航**：居中文字标签 / 左侧分类栏 / 顶部多级菜单。
4. **响应式**：每套给出 390 / 820 / 1440 三档的明确布局变化，而不是同一套断点压缩。

其余可复用：页脚、购物车、AI 客服、SEO 字段。

## 7. 风险

| 风险 | 控制 |
| --- | --- |
| 21 份代码复制导致不可维护 | 三种骨架 + 行业内容块；禁止复制整页组件 |
| 模板切换影响线上 | S4 引入草稿预览与应用确认；先预览再生效 |
| 强调色外溢破坏品牌 | 作用域 CSS + 机械检查（待加） |
| 与项目一提交混杂 | 独立文档、独立分支提交、独立验收 |
| 授权逻辑被模板改写 | 可见性规则只读复用，模板不得自行判断价格可见性 |
| 新依赖 | 本项目不新增依赖；如需，单独 ADR |
